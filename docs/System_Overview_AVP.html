The Problem

From manual logbooks to a unified platform

  • Manual logbooks + disconnected Excel sheets → delayed transactions, inventory discrepancies.
  • No automated validation → overdrawn requests, policy violations, accountability gaps.
  • No real-time asset tracking → misplaced/missing high-value equipment.
  • Seasonal demand spikes (enrollment / graduation) → stock-outs and over-stocks.

Solution: one web platform integrates inventory, requisitions, asset tracking, reporting, and predictive analytics.

Inventory Management & Requisitions System3
Rule-Based Validation

Deterministic business rules before approval

  • Stock availability check — request cannot exceed available stock.
  • Rebate/limit guards and quantity validation (adjustments applied automatically).
  • Requester authorization and role-based access control (RBAC).
  • Duplicate-request detection and institutional policy compliance.
  • Result: an unalterable digital audit trail for every issued item.

Operational control stays transparent and explainable — every approval/rejection is supported by a stated rule, complementing the predictive layer.

Asset Tracking

Barcode accountability & lifecycle

How it works

Each item carries a barcode (LGU-issued or system-generated). Scanning drives registration, issuance, transfer, return, maintenance, verification, and disposal — no GPS/RFID required.

Accountability

Every asset is assigned to a specific accountable person/office. Issuance & Return (RIS) tracks expected return date, actual return, and item condition with overdue detection.

Predictive Analytics — RNN-LSTM

The forecasting engine

  • Input Layer: monthly issuance quantity + month-of-year (captures semester/summer seasonality). Enrollment population data is not used.
  • Hidden LSTM layers: memory cells with input / forget / output gates learn long-term cycles.
  • Dense → Forecast Output: 12-month window predicts next months (MSE loss, 150 epochs, 6 hidden units), 3-month horizon.
  • Validation: MAPE / MAE / RMSE computed on held-out windows, not training data.
  • Retraining: model rebuilds automatically when stock data changes, and on manual retrain — every run is recorded.
